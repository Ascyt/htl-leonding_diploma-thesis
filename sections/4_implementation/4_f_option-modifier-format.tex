This chapter highlights the implementiation of how options and modifiers are handled by the parser. 

The \verb|OptionModifierFormat| class is used to handle specific keywords. It includes two main functions, which are \verb|handle_option| and \verb|handle_modifier|. Each of these functions matches for its respective name. 

\section{Option @NO\_KETOP}

When encountered, the \verb|no_ketop| variable gets enabled in the \verb|current| \\(\verb|FormattedResponse|).

If that variable has already been set to true (i.e.\ if \verb|@NO_KETOP| was used twice in the file) a warning will be logged.

The \verb|@NO_KETOP| option expects no argument. 

\section{Modifier @VERSION}

The \verb|@VERSION| modifier represents a conditional statement and requires an argument.

The argument must be in the form \verb|<component> <comparison> <version>|, where \verb|<component>| is the label of the component that is being checked, \verb|<comparison>| is a comparison operator (either \verb|>|, \verb|<|, \verb|>=|, \verb|<=|, \verb|==|, or \verb|!=|), and \verb|version| is the version to compare the provided component version with, in the \textit{Semantic Versioning} scheme.

The component together with the comparison operator and version will be checked against the \verb|versions| variable provided in \verb|FormatterArgs|, which is a dictionary where the key represents the actual component together with its version on the KeTop. This comparison is case-insensitive and ignores any leading or consecutive whitespace. 

If provided component from the argument is not found in the \verb|versions| dictionary variable, a warning will be logged and the body gets discarded. 

If the comparison is satisfied, the body will be further recursively parsed; otherwise, the body will be discarded. 

The comparison works using the \verb|_compare_versions| function with the following method header:
\begin{lstlisting}[language=Python, caption={Method header of \texttt{_compare_versions}.}, label={lst:method_header_option-modifier-format_compare-versions}]
def _compare_versions(self, actual_version:str, operator:str, compare_version:str) -> bool:
\end{lstlisting}

Here, the \verb|semantic_version| library is used. \textit{Semantic Versioning}, as discussed in Chapter~\ref{chap:keywords-list}, is a standard for assigning and incrementing version numbers.~\cite{SemanticVersioning}

Both the string provided from the \verb|versions| dictionary variable and the one from the argument are attempted to be converted to instances of \verb|semantic_version|'s \verb|Versions| class using its constructor. 

This fails when either of the strings is not in a valid \textit{Semantic Versioning} format. In that case, a warning is logged, and \verb|semantic_version|'s \verb|Version.coerce| method is attempted to be used instead to convert it into a \verb|Version| instance.

According to \verb|semantic_version|'s \gls{api} reference, the rules for \verb|Version.coerce| are as follows:

\begin{itemize}
    \item ``If no minor or patch component, and \verb|partial| is \verb|False|, replace them with zeroes
    \item Any character outside of \verb|a-zA-Z0-9.+-| is replaced with a \verb|-|
    \item If more than 3 dot-separated numerical components, everything from the fourth component belongs to the \verb|build| part
    \item Any extra \verb|+| in the \verb|build| part will be replaced with dots''\cite{py-module-semantic-version-api}
\end{itemize}

If this fails as well, a \verb|ParserSyntaxError|, which is explained in Chapter~\ref{chap:exceptions-and-warnigs}, is raised. 

As \verb|semantic_version| utilizes operator overloading, both versions can be compared using the operators \verb|>|, \verb|<|, \verb|>=|, \verb|<=|, \verb|==|, or \verb|!=| as if they were numbers, where a newer version is considered to be \textit{greater than} an older version.~\cite{py-module-semantic-version-api}. 

A \verb|match| statement is used on the operator string from the argument to choose the corresponding comparison between the version given in the \verb|versions| dictionary and the version from the argument. If an unsupported or otherwise invalid operator is given, a \verb|ParserSyntaxError| is raised.

\section{Modifier @OS}

The \verb|@OS| modifier represents a conditional statement and requires an argument. 

The argument represents the operating system to check; it is compared against the \verb|os| variable provided in \verb|FormatterArgs|. This comparison is case-insensitive ignores any leading whitespace. 

If the provided \verb|os| variable is \verb|None|, a warning will be logged and the body gets discarded. 

If the comparison is satisfied, the body will be further recursively parsed; otherwise, the body will be discarded.

\section{Modifier @PREAMBLE} 

The \verb|@PREAMBLE| modifier continues to recursively parse the body text, however the parsed text will be appended to the respective index of \verb|preamble_dict|, as opposed to \verb|script|. This index is given by the required argument.

This is done by returning a \verb|ChildArgs| instance with the \verb|preamble_index| variable set to that given by the argument. 

A syntax exception will be thrown if it is defined inside \verb|@BRACKETSTART|, \verb|@BRACKETEND| or another instance of \verb|PREAMBLE|.

\section{Modifiers @BRACKETSTART and @BRACKETEND}

The \verb|@BRACKETSTART| or \verb|@BRACKETEND| modifier continue to recursively parse the body text, however the parsed text will be appended to \verb|bracketstart| or \verb|bracketend| respectively, as opposed to \verb|script|. 

This is done by returning a \verb|ChildArgs| instance with \verb|in_bracketstart| or \\\verb|in_bracketend| respectively set to \verb|True|.

A syntax exception will be thrown if it is defined inside \verb|@BRACKETSTART|, \verb|@BRACKETEND| or \verb|@PREAMBLE|.

The \verb|@BRACKETSTART| and \verb|@BRACKETEND| modifiers expect no argument.
